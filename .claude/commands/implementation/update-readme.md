# Update README.md After Code Changes

## When to Use

After any code change that affects:
- Public API (new functions, classes, parameters)
- Installation requirements or dependencies
- Usage examples or functionality
- Project structure or file organization
- Configuration options

## Checklist

Before completing a task involving code changes, check if README.md needs updates:

- [ ] **Installation section**: Updated if dependencies changed
- [ ] **Usage examples**: Updated if API or functionality changed
- [ ] **API reference**: Updated if public interface changed
- [ ] **Configuration**: Updated if config options changed
- [ ] **Project structure**: Updated if files/folders added or removed

## How to Update

1. Read the current README.md
2. Identify sections that need updates based on your code changes
3. Update the relevant sections to reflect the new state
4. Ensure examples in README match the actual API
5. Keep formatting consistent with existing style

## Important Notes

- README.md is the primary documentation for users
- Keep examples copy-pasteable and working
- Update version numbers if applicable
- Document any breaking changes prominently
